# 検証結果

2026年10月20日。NVIDIA DGX Spark / GB10 / Linux aarch64、Isaac Sim **6.0.0-rc.22**（実インストールのVERSIONを確認）で測定した。外部AI API・ROS 2・scikit-learn・システムへの追加インストールは使用していない。

画像分類・物理搬送・通し動作を分けて報告する。以下の成功はシミュレーション内の測定であり、実機での成功率を表さない。

## 到達点

- 小型CNNの学習・独立test評価、輝度しきい値方式との比較。
- 画像だけの判定 → good / defect / review の3トレイへの行先切替。
- UR10e + **Robotiq 2F-85** による接触把持・搬送・開放。吸着、固定ジョイントによる部品の取り付け、搬送中の部品座標の書き換えは行わない。
- 検査画像・スコア・行先・搬送状態のCSV/JSONL、途中結果を含むmetrics JSON。
- 撮影・推論・制御・配置の失敗時停止。評価時だけ明示的に初期状態へリセットして次の試行を行う。
- カメラ画像だけのPNG連番とMP4。デスクトップ、端末、ユーザー名は録画しない。

## 画像分類

300枚 / 150条件グループを生成。train 180枚、val 60枚、test 60枚。各条件の良品・不良品の対は同じ分割に置き、グループと条件の分割間重複を検査した。推論入力は64×64 RGBだけである。モデルは17,225パラメータの小型CNNで、CPU・2 threadsで最初から学習した（記録時間13.0秒）。

| 独立test | CNN | 輝度しきい値 |
|---|---:|---:|
| 全60枚の二値正解率 | **75.0%（45/60）** | 61.7%（37/60） |
| 通常照明30枚 | **100.0%（30/30）** | 73.3%（22/30） |
| 暗照明30枚 | 50.0%（15/30） | 50.0%（15/30） |
| 要確認を除いた採用件数 | 54/60 | 0/60 |
| 採用分の誤り | **13/54（24.1%）** | 未定義 |

要確認はvalだけで決めた確信度しきい値 `0.9996913274226139` を用いる。確信度は `max(p,1-p)`、`p` は不良スコア。testを見てから重み・しきい値を変更していない。testはモデル確定後に1回だけ測定した。

**暗照明では良品15枚すべてを不良品と誤認し、うち13枚を要確認でも止められなかった。** 通常照明での成功から、照明変化・実機・未知カメラへの性能を一般化しない。詳細、混同行列、要確認率、画像の残像の限界は [CLASSIFICATION.md](CLASSIFICATION.md)、公開用の測定要約は [classification_metrics.json](classification_metrics.json) にある。

## 搬送の成功判定と試行条件

部品は 0.100 × 0.0515 × 0.060 m、0.20 kgの同形状の直方体。既知の検査位置と姿勢へ1個ずつ供給する。各試行の前にロボットの関節と部品を固定初期状態へ戻す**独立episode**である。連続供給機、位置・姿勢の自動推定、トレイへの20部品の蓄積は対象外。

制御は200 Hz。実EE位置からCartesian直線の目標を作り、Lula IKと速度制限付き関節指令を使う。降下0.04 m/s、上昇0.08 m/s、水平搬送0.12 m/s。2F-85のパッド形状からEEオフセットを0.13 mとした。指は0.4 rad/sで開閉し、drive damping 2 / maxForce 8、mimicはアセットの既定値を保持する。詳細は [85プロファイル](../src/sorter/planning/profiles/ur10e_85/README.md)。

ロボットの動作相の完了だけでは成功にしない。次の条件を検査する。

1. 持ち上げ後に部品が供給位置より0.06 mを超えて高いこと。
2. 開放後、回転を含めた部品全体のAABBが選んだトレイの内部に収まること。
3. 部品下面とトレイ床の距離が0.012 m以内であること。
4. 指を開き、退避した後に、並進速度 < 0.015 m/s・角速度 < 0.15 rad/sが連続60物理ステップ（0.30秒）続くこと。
5. 良否の確定行先は画像の正解と一致すること。reviewは保留処理として別計数し、分類正答とは扱わない。

閉じた指には接触による数値振動があるため、閉動作の保持時間だけで把持成功とはしない。その後の実際の持ち上げと最終配置で成否を測る。開放時は指位置と速度も確認する。

`config/demo_conditions.json` の3条件は、valから3経路の接続確認用に選んだものである。毎回シミュレータで再撮影して画像だけで行先を決め、設定ファイルから行先を強制しない。これは固定条件での搬送とシステム接続の測定であり、分類の独立test精度の分母には加えない。

## 起動・把持で見つかった失敗

| 失敗 | 原因・対応 | 測定した事実 |
|---|---|---|
| 前回のapp ready後の停止 | ネットワーク依存のasset root存在確認に同期statの待ちがあるため、その可能性がある。床をプリミティブ化し個別アセットを直接参照 | 今回のコピー直後の再実行では停止を再現せず、搬送まで進んだ |
| サンプルが2F-85と一致しない | 元USDは2F-140 variantだった | native UR10e + 2F-85 variantへ交換して検証 |
| EEの姿勢誤差がπのまま停止 | 旧URDFの固定関節回転とUSDが逆 | 85用の関節定義を作成。静的誤差1e-6以内、実EE/FKの一致を確認 |
| 腕が降下目標の約35 mm手前で停滞 | 実関節位置を基準とした微小指令が負荷に負けた可能性（トルク自体は未計測） | 前回指令から速度制限付きで積分し、実位置で収束を確認 |
| 降下中に部品を横へ押し出す | 指先高さと関節空間の曲線経路 | パッド形状からオフセットを定義し、垂直Cartesian経路へ変更 |
| 接触中の指振動で閉動作がtimeout | 閉じた指の瞬時速度を必須停止条件にしていた | 閉動作は所定時間保持し、実持ち上げ・開放後のトレイ内静止で成功を確認 |
| カメラ画像が単色 | 既定near clipより部品が近い | near=0.01 mを指定し、画像の更新・品質を検査 |
| 一部の良品画像に薄い汚れの残像 | レンダー履歴の影響が残る | 同じ生成手順のtestで評価し、実機の清浄面と同一とは扱わない |

調整途中の失敗ログ・metricsも `artifacts/` に残した。異なる機構・設定・成功基準の試行を、凍結設定の20試行に混ぜていない。
